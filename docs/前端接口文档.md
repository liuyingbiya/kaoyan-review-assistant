## 一、数据模型

### 科目 `Subject`

三级树：**公共课 / 专业课 → 模块 → 具体科目**

```
公共课
├─ 英语
│  ├─ 英语一    english1   ← 可提问
│  └─ 英语二    english2   ← 可提问
├─ 数学
│  ├─ 数学一    math1      ← 可提问
│  ├─ 数学二    math2      ← 可提问
│  ├─ 线性代数  linear      ← 可提问
│  └─ 概率论与数理统计 prob  ← 可提问
└─ 政治        politics    ← 可提问

专业课
└─ 408 专业课
   ├─ 数据结构  ds          ← 可提问
   └─ 操作系统  os          ← 可提问
```

**只有叶子节点能提问**（共 9 个）。`english`、`math`、`politics`、`cs408` 这些是分组，不存资料。

字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | string | 科目编码，提问时传这个 |
| `name` | string | 显示名 |
| `category` | string | `公共课` / `专业课` |
| `parentCode` | string? | 父级编码，顶级为 null |
| `sort` | int | 排序 |
| `intro` | string? | 一句话说明 |
| `children` | Subject[] | 子节点 |
| `docCount` / `chunkCount` | int | 该科目下资料数 / 片段数 |

## 二、接口清单

### 1. 科目树

```
GET /api/subjects
```

返回根节点数组（公共课、专业课），子节点在 `children` 里。

```json
[
  {
    "code": "public", "name": "公共课", "category": "公共课", "parentCode": null,
    "children": [
      {
        "code": "english", "name": "英语",
        "children": [
          { "code": "english1", "name": "英语一", "docCount": 1, "chunkCount": 4, "children": [] },
          { "code": "english2", "name": "英语二", "docCount": 1, "chunkCount": 3, "children": [] }
        ]
      },
      { "code": "math", "name": "数学", "children": [
          { "code": "math1", "name": "数学一", "docCount": 1, "chunkCount": 3, "children": [] },
          { "code": "linear", "name": "线性代数", "docCount": 1, "chunkCount": 4, "children": [] }
      ]},
      { "code": "politics", "name": "政治", "docCount": 1, "chunkCount": 3, "children": [] }
    ]
  },
  { "code": "pro", "name": "专业课", "children": [ ... ] }
]
```

### 2. 扁平科目列表（做下拉框用）

```
GET /api/subjects/flat
```

返回 `[{code, name, category, parentCode, docCount}]`，自己按 `docCount > 0` 过滤。

### 3. 模型状态

```
GET /api/chat/status
```

```json
{ "mock": false, "model": "deepseek-chat", "hint": "已接入 DeepSeek" }
```

`mock=true` 时是本地模拟模式（没配 key），前端可以显示一个提示条。

### 4. 流式问答 ★核心

```
GET /api/chat/stream?subjectCode=os&question=死锁的四个必要条件是什么？&sessionId=1
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `subjectCode` | 是 | 叶子科目编码，限定在这科资料里检索 |
| `question` | 是 | 问题，中文会自动 URL 编码 |
| `sessionId` | 否 | 多轮对话时传上一轮返回的 id |

**响应是 SSE**，每行一个 JSON，靠 `type` 区分：

```
data: {"type":"meta","sessionId":1,"subjectCode":"os","model":"deepseek-chat","mock":false}
data: {"type":"delta","text":"死锁的"}
data: {"type":"delta","text":"四个必要"}
data: {"type":"citations","items":[{"docId":1,"docTitle":"操作系统核心考点","seq":4,"score":2.13,"content":"死锁的四个必要条件：互斥、占有并等待…"}]}
data: {"type":"done","chars":220}
data: {"type":"error","message":"大模型接口返回 401"}
```

前端用 `EventSource` 消费：

```js
const es = new EventSource(
  `/api/chat/stream?${new URLSearchParams({ subjectCode, question })}`
)
es.onmessage = (e) => {
  const ev = JSON.parse(e.data)
  if (ev.type === 'meta') { sessionId.value = ev.sessionId }
  if (ev.type === 'delta') { draft.value += ev.text }        // 边收边渲染
  if (ev.type === 'citations') { citations.value = ev.items }
  if (ev.type === 'done') { es.close(); /* 把 draft 转成正式消息 */ }
  if (ev.type === 'error') { es.close(); ElMessage.error(ev.message) }
}
es.onerror = () => es.close()
```

> ⚠️ 注意：`EventSource` 只能发 GET，所以问题放在 query 里。
> 长问题也没问题（浏览器 URL 上限足够），但要用 `URLSearchParams` 让它自动编码中文。

### 5. 会话

```
GET    /api/sessions?subjectCode=os        → 该科目的会话列表
GET    /api/sessions/recent?limit=5        → 最近会话（跨科目，首页用）
GET    /api/sessions/{id}/messages         → 某会话的全部消息
PUT    /api/sessions/{id}?title=新标题      → 重命名
DELETE /api/sessions/{id}                  → 删除（消息级联删除）
```

会话对象：`{id, subjectCode, subjectName, title, createdAt}`
消息对象：`{id, sessionId, role, content, citations, createdAt}`
`role` 是 `user` / `assistant`；`citations` 是 **JSON 字符串**，前端要 `JSON.parse` 后才是数组。

---

### 6. 资料管理

```
GET    /api/kb/docs?subjectCode=os          → 该科目资料列表
GET    /api/kb/docs/all                     → 全部资料（管理页）
GET    /api/kb/stats?subjectCode=os         → {subjectCode, docs, chunks}
POST   /api/kb/import                       → 粘贴文本导入（JSON）
POST   /api/kb/upload                       → 上传 .txt/.md（multipart）
DELETE /api/kb/docs/{id}                    → 删除资料
```

**导入（JSON）**：

```json
POST /api/kb/import
{ "subjectCode": "os", "title": "我的操作系统笔记", "content": "正文……" }
```

**上传（multipart）**：

```
POST /api/kb/upload
字段：file（文件）、subjectCode=os、title=可选
```

资料对象：`{id, subjectCode, subjectName, title, source, charCount, chunkCount, createdAt}`

## 三、错误格式

所有非 SSE 接口出错时返回 HTTP 4xx/5xx + 统一 JSON：

```json
{ "message": "科目不存在: xxx" }
```

前端统一提示 `message` 即可。

## 四、前端页面建议

| 页面 | 内容 |
|---|---|
| 左侧栏 | 科目树（`el-tree` 或折叠面板），只有 `docCount > 0` 的叶子可点；下面放该科目的会话列表 |
| 主区 | 对话窗口：消息气泡 + 流式打字效果 + 引用来源折叠块 |
| 引用块 | 显示 `docTitle`、第几段、相关度分数、片段正文 —— 这是 RAG 的卖点，别省掉 |
| 资料管理 | 弹窗里放资料表格 + 导入按钮（粘贴文本 / 上传文件） |

**交互细节**：
- 流式期间禁用发送按钮，显示"正在生成…"
- 切科目时清空当前会话（换科目就该重新开始）
- 引用来源用 `el-collapse` 收起，默认折叠，别让长文挤满屏幕

## 五、开发环境

前端**不需要构建**：它由后端直接托管，打开 `http://localhost:8081` 就是完整页面。

```powershell
.\run.ps1 -Key "sk-xxx"      # 启动后端（同时把前端一起提供）
```

改前端只需要：改 `frontend/` 下的文件 → **强刷浏览器（Ctrl+F5）**。

> 原理：`application.properties` 里配了
> `spring.web.resources.static-locations=file:../frontend/,classpath:/static/`
> 开发时优先读仓库里的 `frontend/` 目录，所以改完立刻生效，不用重新打包。
> 打包成 jar 时前端会被复制进 `static/`，那时读的是 classpath 那份。

前端源码结构：

```
frontend/
├─ index.html            引入 vue / element-plus / 业务代码（顺序不能乱）
├─ css/app.css
└─ js/
   ├─ api.js             接口封装（fetch + openChatStream）
   ├─ app.js             入口：串组件、管全局状态
   └─ components/
      ├─ subject-tree.js
      ├─ session-list.js
      ├─ chat-panel.js
      └─ kb-manager.js
```

如果你确实想改成 Vite 工程：把 `js/` 下的组件改成 `.vue` 单文件、`vendor/` 换成 npm 依赖、
在 `vite.config.js` 里把 `/api` 代理到 8081 即可。**现有后端不用改**。
