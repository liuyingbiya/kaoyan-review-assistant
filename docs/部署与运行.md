# 部署与运行

## 一、本地运行（推荐）

### 前置条件

| 依赖 | 版本 | 本机位置 |
|---|---|---|
| JDK | **1.8** | `E:\envriorment\java` |
| Maven | 3.8.4 | `E:\envriorment\maven\apache-maven-3.8.4` |
| MySQL | 8.0 | Windows 服务 `MySQL80` |

> ⚠️ 必须用 JDK 8。用 17/21 启动会在反射和字节码上出问题（Spring Boot 2.7 + JDK8 组合）。

### 1. 建库

```powershell
cd backend
mysql -uroot -proot --default-character-set=utf8mb4 -e "source schema.sql"
```

执行后会得到：

- `subject`：14 个科目节点（三级树）
- `kb_doc` / `kb_chunk`：资料与切片（`content` 上有 ngram 全文索引）
- `chat_session` / `chat_msg`：会话与消息

验证：

```sql
USE ai_kb;
SELECT COUNT(*) FROM subject;        -- 14
SELECT code, name, parent_code FROM subject ORDER BY sort;
```

### 2. 启动

```powershell
# 真实模型
.\run.ps1 -Key "sk-你的DeepSeekKey"

# 模拟模式（不传 key）
.\run.ps1

# 改了代码后
.\run.ps1 -Rebuild -Key "sk-xxx"
```

打开 http://localhost:8081

首次启动会自动导入 `seed/` 下的 9 篇资料。日志里能看到：

```
导入资料 [英语一·english1] 英语一题型与复习重点 -> 4 个片段
...
初始资料处理完成：新导入 9 篇，已存在跳过 0 篇
```

### 3. 跑测试

```powershell
node tests\verify-api.js
cd tests; node verify-ui.js
```

预期：`35 项通过` + `22 项通过`。

## 二、IDEA 里运行

1. `File → Open` 选 `backend/pom.xml` → `Open as Project`
2. `Project Structure → Project`：SDK 选 **1.8**，Language level 选 8
3. `Settings → Build Tools → Maven`：User settings file 指向 `backend/.mvn/settings.xml`（勾 Override）
4. 新建运行配置：
   - Main class：`com.aikb.AiKbApplication`
   - Working directory：`...\ai项目\backend`
   - VM options：`-Dfile.encoding=UTF-8 -Djava.io.tmpdir=...\ai项目\.runtime`
   - Environment variables：`DEEPSEEK_API_KEY=sk-xxx`

> 工作目录必须是 `backend`，因为 `rag.seed-dir=../seed` 是相对路径。

## 三、Docker 部署

```powershell
$env:DEEPSEEK_API_KEY="sk-xxx"
docker compose up --build
```

- 应用：http://localhost:8081
- MySQL：`localhost:3307`（映射到容器 3306，避免和本机 3306 冲突）

`docker-compose.yml` 里 `depends_on` 用了 `condition: service_healthy`，会等 MySQL 真正能接受连接后再启动应用。

## 四、常见问题

### 1. 中文乱码成 `???`

JVM 默认编码是 GBK。必须加 `-Dfile.encoding=UTF-8`。
⚠️ 但**不要**加 `-Dsun.jnu.encoding=UTF-8` —— 会让 JVM 无法打开中文路径下的自己的 jar。

### 2. `Unable to create tempDir`

Tomcat 需要可写临时目录，加 `-Djava.io.tmpdir=<项目>\.runtime`。

### 3. 检索什么都查不到

按顺序排查：

```sql
-- ① 资料导进去了吗
SELECT COUNT(*) FROM kb_doc;
SELECT COUNT(*) FROM kb_chunk;

-- ② 全文索引存在吗（必须有 ngram）
SHOW INDEX FROM kb_chunk WHERE Index_type = 'FULLTEXT';

-- ③ 直接试一条检索
SELECT content, MATCH(content) AGAINST('死锁' IN NATURAL LANGUAGE MODE) AS score
FROM kb_chunk WHERE subject_code = 'os' LIMIT 3;
```

如果 ③ 返回 score 全是 0，说明索引不是用 ngram 建的 —— 重跑 `schema.sql`。

### 4. `mock: false` 但回答报 401

Key 无效或已撤销。检查环境变量：

```powershell
$env:DEEPSEEK_API_KEY
```

### 5. 端口 8081 被占用

之前启动的进程没退干净：

```powershell
Get-NetTCPConnection -LocalPort 8081 -State Listen | Select-Object OwningProcess
Stop-Process -Id <上面查到的PID>
```

### 6. 改了前端没生效

开发模式下 Spring Boot 会优先读 `file:../frontend/`，改完**强刷浏览器**（Ctrl+F5）。
如果还是旧页面，说明是从 jar 里读的 classpath 那份 —— 重新 `-Rebuild` 打包。
