# 操作系统 · 核心考点框架

## 进程与线程

进程是资源分配的基本单位，线程是 CPU 调度的基本单位。同一进程内的线程共享地址空间与打开的文件，但各自有独立的栈和寄存器上下文。

线程开销更小：创建线程不需要新地址空间；线程切换只保存少量寄存器，而进程切换还要切换页表、刷新 TLB。

进程三种基本状态：就绪、运行、阻塞。**阻塞的进程不能直接转为运行态，必须先回到就绪态。**

## 调度算法

先来先服务（FCFS）：按到达顺序，实现简单，但短作业吃亏（护航效应）。
短作业优先（SJF）：平均等待时间最短，但需预知运行时间，长作业可能饥饿。
时间片轮转（RR）：响应快，适合分时系统；时间片过大退化为 FCFS，过小则切换开销大。
优先级调度：可能导致低优先级饥饿，解决办法是"老化"。
多级反馈队列：兼顾响应时间与吞吐量，是现代通用系统的常用做法。

## 同步与互斥

临界区是访问共享资源的代码段。互斥要求同一时刻只有一个进程进入；同步要求按特定顺序执行。

信号量：P 操作（wait）申请资源，减一后若小于 0 则阻塞；V 操作（signal）释放资源，加一后若有等待进程则唤醒。实现互斥时初值为 1，实现同步时初值通常为 0。

经典问题：生产者—消费者（两个同步信号量 empty/full + 一个互斥信号量 mutex）；读者—写者（读读共享、读写互斥、写写互斥）；哲学家进餐（破坏循环等待，如限制最多四人同时拿筷子）。

## 死锁

四个必要条件：互斥、占有并等待、不可剥夺、循环等待。四个同时成立才可能死锁，破坏任一即可预防。

处理策略：
- 预防：静态分配资源、允许剥夺、按序申请资源
- 避免：银行家算法，分配前判断系统是否仍处于安全状态
- 检测与解除：检测资源分配图是否有环，有环则撤销进程或剥夺资源

## 内存管理

分页：逻辑空间与物理内存都划分为固定大小的页，通过页表映射。无外部碎片，但需要两次访存，因此引入 TLB 缓存页表项。
分段：按逻辑结构划分，便于共享与保护，但产生外部碎片。
段页式：先分段再分页，兼顾两者。

页面置换算法：
- OPT（最佳置换）淘汰未来最久不用的页，无法实现，仅作衡量标准
- FIFO 实现简单，但存在 **Belady 异常**（增加页框数反而缺页更多）
- LRU 淘汰最久未访问的页，效果接近 OPT，但需要硬件支持
- Clock（时钟算法）是 LRU 的近似，用访问位循环扫描，开销小
